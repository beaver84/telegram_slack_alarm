# Claude Code 알림 (Slack + Telegram) 설정 가이드

LEVEL 4 강의(4.1 Slash Command · 4.3 Hook)의 알림 Hook 패턴을 이 프로젝트에 적용한 문서입니다.
Claude가 **입력/권한을 요청**하거나 **작업을 마치면** Slack과 Telegram으로 메시지가 전송됩니다.

## 구성 파일

| 파일 | 역할 | 강의 대응 |
|---|---|---|
| `.claude/hooks/notify.mjs` | 알림 전송 스크립트 (Slack + Telegram) | 4.3.4 알림 Hook |
| `.claude/settings.json` | `Notification`, `Stop` 이벤트에 훅 등록 | 4.3.1 이벤트 / 4.3.4 등록 예시 |
| `.claude/commands/notify-test.md` | `/notify-test` 테스트 커맨드 | 4.1.3 커스텀 커맨드, 4.1.4 `$ARGUMENTS` |

### 강의 예시와 다른 점

강의의 `notify-slack.sh`는 bash + `jq` + `curl` 기반입니다. Windows에는 `jq`가 기본으로 없어 훅이 조용히 실패할 수 있습니다(강의 4.3.7 주의사항).
이 프로젝트는 Node 프로젝트이므로 **Node 내장 `fetch`** 로 작성했습니다. 추가 설치가 필요 없고 Windows/macOS/Linux에서 동일하게 동작합니다.

## 동작 방식

```
Claude 이벤트 (Notification / Stop)
  -> settings.json 의 hook 실행
  -> stdin 으로 JSON 페이로드 전달 (hook_event_name, message, cwd ...)
  -> notify.mjs 가 메시지 생성
  -> Slack Webhook / Telegram Bot API 로 동시에 POST
  -> 항상 exit 0 (Claude 동작을 막지 않음)
```

- 환경변수가 없는 채널은 **조용히 건너뜁니다** (강의의 "Webhook URL 미설정 시 silent exit"와 동일).
- 한 채널이 실패해도 다른 채널은 전송됩니다. 실패 사유는 stderr에 `notify slack failed: ...` 로 남습니다.
- 요청 타임아웃은 5초입니다 (훅은 빨리 끝나야 한다는 강의 4.3.7 원칙).

## 단계별 설정

### 1단계. Slack Webhook 만들기

1. https://api.slack.com/apps 에서 **Create New App** -> From scratch
2. 좌측 **Incoming Webhooks** -> 활성화(On)
3. **Add New Webhook to Workspace** -> 알림 받을 채널 선택
4. 발급된 URL(`https://hooks.slack.com/services/...`) 복사

### 2단계. Telegram 봇 만들기

1. Telegram에서 **@BotFather** 검색 -> `/newbot` -> 이름/아이디 입력 -> **Bot Token** 받기
2. 만든 봇과 대화를 열고 아무 메시지(`/start`)를 보냅니다. (그룹에 쓰려면 봇을 그룹에 초대)
3. 브라우저에서 아래 URL 열기 (토큰 교체):
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
4. 응답 JSON의 `message.chat.id` 값이 **Chat ID** 입니다. (그룹은 음수)

### 3단계. 환경변수 등록

키는 파일에 적지 않고 사용자 환경변수에 둡니다 (강의 4.4.3, `.mcp.json`과 같은 원칙 — 커밋 한 번이면 유출).

PowerShell:

```powershell
setx SLACK_WEBHOOK_URL "https://hooks.slack.com/services/XXX/YYY/ZZZ"
setx TELEGRAM_BOT_TOKEN "123456:ABC..."
setx TELEGRAM_CHAT_ID "123456789"
```

> `setx`는 **새 터미널부터** 적용됩니다. 등록 후 터미널과 Claude Code를 재시작하세요.
> 확인: `echo $env:SLACK_WEBHOOK_URL`

macOS/Linux는 `~/.zshrc` 또는 `~/.bashrc`에 `export NAME="..."` 후 `source` 합니다.

### 4단계. 테스트

전송 없이 메시지 형태만 확인 (dry-run):

```bash
echo '{"hook_event_name":"Notification","message":"테스트"}' | NOTIFY_DRY_RUN=1 node .claude/hooks/notify.mjs
```

실제 전송은 Claude Code 안에서:

```
/notify-test            # 실제 전송
/notify-test dry-run    # 전송 없이 출력만
```

Slack 채널과 Telegram 대화에 메시지가 도착하면 성공입니다.

### 5단계. 훅 등록 확인

`.claude/settings.json`:

```json
{
  "hooks": {
    "Notification": [{ "hooks": [{ "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/notify.mjs\"" }] }],
    "Stop":         [{ "hooks": [{ "type": "command", "command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/notify.mjs\"" }] }]
  }
}
```

- `Notification`: Claude가 권한/입력을 요청할 때
- `Stop`: Claude 응답이 끝났을 때

Claude Code에서 `/hooks` 로 등록 상태를 볼 수 있습니다. 설정을 바꾼 뒤에는 세션을 재시작하세요.

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| 아무 알림도 안 옴 | 환경변수 미설정 또는 터미널 재시작 안 함. `echo $env:SLACK_WEBHOOK_URL` 로 확인 |
| `notify slack failed: HTTP 404/403` | Webhook URL 오류 또는 폐기됨. 재발급 |
| `notify telegram failed: HTTP 400` | `chat_id` 오류, 또는 봇에게 먼저 메시지를 보내지 않음 |
| `notify telegram failed: HTTP 401` | Bot Token 오류 |
| 훅이 발화하는지 모르겠음 | `claude --debug` 로 훅 발화/exit code/stderr 추적 |
| 매 응답마다 알림이 너무 많음 | `settings.json` 에서 `Stop` 항목 제거 (Notification만 유지) |

## 보안 주의

- Webhook URL, Bot Token은 **저장소에 커밋하지 마세요.** 환경변수로만 관리합니다.
- 훅은 사용자 권한으로 자동 실행됩니다 (강의 4.3.7). `notify.mjs`는 외부 두 엔드포인트로 메시지만 전송합니다.
- 메시지에는 프로젝트 폴더명과 Claude 알림 문구만 포함되며, 코드나 파일 내용은 전송하지 않습니다.
