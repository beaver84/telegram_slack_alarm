# Slack 웹훅 알림 동작 원리

`#한줄회고` 채널에 메시지가 도착하기까지의 과정을 정리한 문서입니다.
설정 방법은 [슬랙-웹훅-설정.md](./슬랙-웹훅-설정.md), 전체 구성은 [알림-설정-가이드.md](./알림-설정-가이드.md)를 참고하세요.

## 1. 왜 `#한줄회고` 채널로 갔나

Webhook URL은 **발급 시 선택한 채널에 묶여** 있습니다.

- Slack 앱 설정 화면의 **Add New Webhook to Workspace**에서 `#한줄회고`를 선택했습니다.
- 그 결과 생성된 URL로 보내는 메시지는 항상 그 채널에 게시됩니다.
- 요청 본문에 채널을 따로 적지 않아도 됩니다.

URL 구조:

```
https://hooks.slack.com/services/T6F2L7FLG / B0C9UJN4A3X / <비밀 토큰>
                                  워크스페이스    앱(봇)       인증 토큰
```

토큰을 아는 사람은 누구나 이 채널에 메시지를 쓸 수 있습니다. 그래서 URL은 비밀번호처럼 다룹니다.

채널에 보이는 "Claude Alarm 통합 기능을 추가했습니다" 줄은 Webhook 생성 시 Slack이 자동으로 남긴 기록입니다.

## 2. 전체 흐름

```
Claude Code 이벤트 (Notification / Stop)
   |
   v
.claude/settings.json 의 hook 명령 실행
   node .claude/hooks/notify.mjs
   |  stdin: {"hook_event_name":"Notification","message":"...","cwd":"..."}
   v
notify.mjs
   1) stdin JSON 파싱
   2) 메시지 생성  "🔔 [Claude Code] <폴더명>\n<message>"
   3) 환경변수 SLACK_WEBHOOK_URL 로 fetch POST  {"text": "..."}
   |
   v
Slack 서버: URL 토큰 확인 -> 연결된 채널(#한줄회고)에 "Claude Alarm" 앱 이름으로 게시
```

### 단계별 설명

1. **이벤트 발생**: Claude가 권한/입력을 요청하면 `Notification`, 응답을 마치면 `Stop`이 발생합니다.
2. **훅 실행**: `settings.json`에 등록된 `node .claude/hooks/notify.mjs`가 실행됩니다.
3. **stdin 전달**: 이벤트 정보가 JSON으로 표준입력에 들어옵니다.
4. **메시지 생성**: `cwd`의 폴더명과 `message`를 조합합니다. (`Stop`은 "작업이 끝났습니다.")
5. **전송**: `fetch`로 Webhook URL에 `Content-Type: application/json`, 본문 `{"text":"..."}`를 POST합니다.
6. **게시**: Slack이 토큰을 검증하고 연결된 채널에 게시합니다. 성공 응답은 `ok`(HTTP 200)입니다.
7. **종료**: Telegram 환경변수가 없으면 건너뛰고, 항상 exit 0으로 끝나므로 Claude 작업을 방해하지 않습니다.

## 3. 테스트 때 메시지가 2개 온 이유

| 순서 | 메시지 | 출처 |
|---|---|---|
| 1 | `webhook ?▯?⎡ (Claude Code)` | bash에서 `curl`로 직접 보낸 URL 검증 테스트 |
| 2 | `🔔 [Claude Code] telegram_slack_alarm / 훅 연동 테스트` | `notify.mjs` 훅 스크립트 |

첫 번째 메시지의 한글이 깨진 것은 **훅의 문제가 아닙니다.** Git Bash에서 `curl -d`로 한글을 보낼 때 인코딩이 UTF-8로 전달되지 않아 생긴 현상입니다.
`notify.mjs`는 `JSON.stringify`로 UTF-8 본문을 보내므로 한글이 정상 표시됩니다.

## 4. 트러블슈팅 기록

### Windows에서 `process.exit(0)` 크래시

- 증상: `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 76`
- 원인: `fetch` 연결이 닫히는 중에 `process.exit()`를 호출하면 Windows의 Node(libuv)가 assertion으로 비정상 종료합니다.
- 해결: `process.exit(0)` 대신 `process.exitCode = 0`을 설정하고 이벤트 루프가 자연스럽게 끝나게 했습니다.
- 파일: `.claude/hooks/notify.mjs`

## 5. 확인 상태

| 항목 | 상태 |
|---|---|
| Webhook URL 유효성 (curl, HTTP 200 `ok`) | 확인 |
| `notify.mjs` 수동 실행 후 채널 도착 | 확인 |
| 환경변수 `SLACK_WEBHOOK_URL` 등록 (`setx`) | 완료, 새 터미널부터 적용 |
| 실제 `Notification` / `Stop` 이벤트로 자동 발화 | 미확인. 새 세션에서 확인 필요 |
| Telegram 연동 | 미설정 |

## 6. 보안 메모

- 설정 과정에서 Webhook URL이 대화와 스크린샷에 노출되었습니다.
- 우려되면 api.slack.com/apps -> Claude Alarm -> Incoming Webhooks에서 해당 Webhook을 삭제하고 재발급한 뒤 `setx SLACK_WEBHOOK_URL`을 다시 실행합니다.
- URL은 저장소에 커밋하지 않습니다. 환경변수로만 관리합니다.
